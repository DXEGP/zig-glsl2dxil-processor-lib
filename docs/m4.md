# M4：内存输入、真实包与编译会话

M4 保留纯 Zig GLSL→AST→语义→SSA→DXIL 管线，新增内存 VFS、宏配置、来源映射、有界缓存和可选优化。Minecraft Java 1.21.4 优先；本地两个 Iris 包用于记录可编译部分与实际阻塞。通过部分阶段不代表能够运行整个游戏或光影包。

## 输入与预处理

Zig `GraphicsRequest.preprocessing` 接受 `files`、`defines`、`include_dirs`、`limits`。名称与源码在调用期间借用；成功结果和失败诊断各自持有所需文本。核心不读取磁盘、压缩包或网络，测试宿主负责加载。单独调用 `processor.source.preprocess` 时使用调用者 arena 管理临时数据与结果的统一生命周期。

- 路径区分大小写，统一 `/`，折叠 `.` 与合法 `..`；拒绝根目录逃逸、盘符、NUL、重复规范化路径及超过 4096 字节的路径。
- `#include "name"` 依次查找包含文件目录、VFS 根、显式 include 目录；`<name>` 跳过相对目录；`/name` 从虚拟根查找。
- `#moj_import <minecraft:fog.glsl>` 查找 `assets/minecraft/shaders/include/fog.glsl`，默认 namespace 为 `minecraft`。import 每阶段展开一次；普通 include 使用 guard／`#pragma once`，递归越限返回诊断。
- 支持对象宏、固定参数函数宏、跨行调用、续行、参数预展开、别名重扫与递归抑制。条件表达式支持 `defined`、整数／位运算、比较、逻辑短路与 `?:`，在编译时求值。
- `__VERSION__` 使用入口版本，包含文件不覆盖它；`__LINE__` 为原始行号，`__FILE__` 为每阶段依赖首次出现的编号，从 0 开始。
- token 映射保存文件／行／列；宏替换映射到调用位置，包含文件保留自身位置。`GraphicsResult.dependencies` 返回传递依赖与 SHA256，共同 include 可在两阶段各出现一次。
- variadic、`#`／`##`、显式 `#line` 重映射和启用任意扩展暂不支持，均有诊断。非兼容宏重定义要求先 `#undef`；未知指令拒绝，普通 pragma 作为提示忽略。

默认每文件 1 MiB，VFS 总输入及累计扫描各 32 MiB，输出 4 MiB，扫描／展开 token 上限 524288，宏工作步骤 1048576，include／宏深度 64，条件／表达式深度 128。配置列表总项数也受 token 上限限制。0 表示禁止相应工作。DXIL 另保留入口 1 MiB、lexer 262144 tokens、IR 4096 blocks／1000000 values 等既有上限，增大预处理配置不会取消这些限制。

## Zig 与 C/C++ 接口

```zig
var session = processor.CompileSession.init(allocator, .{
    .entries = 32, .bytes = 64 * 1024 * 1024,
});
defer session.deinit();
var result = try session.compile(.{
    .vertex = .{ .name = "main.vert", .source = vertex },
    .fragment = .{ .name = "main.frag", .source = fragment },
    .preprocessing = .{
        .files = &.{.{ .name = "lib/color.glsl", .source = library }},
        .defines = &.{.{ .name = "QUALITY", .value = "2" }},
    },
    .optimization = .safe,
}, &diagnostics);
defer result.deinit();
```

无缓存时仍用 `processor.compileGraphics`。C 新增 `glsl2hlsl_dxil_compile_graphics_v2`，嵌套 `base: options_ex` 的两个 `struct_size` 均须填写；旧 options／options_ex／result 布局不变。session 为 NULL 时不缓存，`limits` 为 NULL 时使用默认值，`optimization` 为 0（关闭）或 1（safe）。新增 session create/free/stats，结果继续使用原 graphics result free。

C++ `GraphicsRequest` 增加 `files`、`defines`、`include_dirs`、`limits`、`optimize`、`session`。只移动的 `CompileSession.get()` 可填入请求；创建失败时返回空指针，需要缓存的宿主应先检查。范例见 `tests/dxil/capi_test.c` 与 `tests/cpp/interop_test.cpp`。

## 缓存与优化

会话使用 LRU，默认 32 条／64 MiB，容量为 0 则不保存。字节上限计算保留 arena 容量与共享控制块，条目数组有额外元数据；调用者持有的已驱逐结果不计入缓存占用。返回值共享不可变数据、各持有引用，驱逐或释放会话不使既有结果失效，每份结果须释放一次。

SHA256 键包含缓存／编译格式修订、两个源码及名称、**全部** VFS 内容与顺序、宏、include 目录、限制、目标、坐标、绑定／堆布局和优化。未使用文件变化也保守失效；命中包含完整输入哈希成本。失败不缓存，成功警告在命中时复制。独立会话可并行；同一会话及共享结果的 retain/free 须由宿主串行化。没有全局或磁盘缓存。

`.safe` 仅做同基本块纯表达式 CSE 和无用纯指令消除，保留操作顺序与浮点位语义，不做代数化简，不合并／提升 intrinsic、纹理／cbuffer 读取或 discard；前后均验证类型、支配关系与 PHI。默认 `.none`：本次两份真实 Minecraft 样例的产物缩小，但编译 P50 均上升，因此不默认开启。

真实输入同时修复两处缺陷：资源／接口继续确定性排序，全局初始化改按源码声明顺序执行；无输入／输出的 PSV 不再写签名元素大小字段。

## 验收与性能复现

```powershell
pwsh -NoProfile -File tests/dxil/m4.ps1
```

完整脚本保留 M1–M3、静态／共享 C23 与 C++23/26、既有 HLSL 回归，生成真实包清单、官方验证、基准及 GPU 报告。支持 `-Dxc <path>`；`-SkipHardware` 只算部分验收。单独重跑：

```powershell
pwsh -NoProfile -File tests/dxil/m4_inputs.ps1
zig build dxil-m4 dxil-m4-bench -Doptimize=ReleaseSafe
```

GPU 逐像素比较 16×16 颜色／深度：原样 Minecraft position_color、position＋fog include 的两种 FogShape，Iris 原样 discard/no-op，以及既有控制流／资源／坐标和新增常量依赖／CSE 场景。Intel UHD 跑 6.5，RTX 5070 Laptop 跑三种配置，均比较优化开关；PSO 成功不代替像素正确。

基准对两份 Minecraft 配对及三档重复算术输入，每种目标／优化测首次和 101 次无缓存 P50/P95/P99，另测 101 次命中。预处理、解析、语义、SSA、优化、编码分别报告分位数，不能相加各阶段独立分位数。计数 allocator 禁用 resize/remap，内存为请求峰值而非 RSS；文件读取、释放、validator、PSO 不计入编译时间。

输出：`zig-out/m4/support.json`（逐项诊断／依赖／阶段／产物清单）、`benchmark.json`、`validation.txt`、`render.txt`、`report.json`。后者记录工具／包／产物摘要、CPU、系统、适配器及驱动。PSO 微秒单列，OS／驱动缓存未受控，不能称冷驱动耗时。数值以本次机器报告为准，`0.1–0.8 ms` 仍不是保证。
